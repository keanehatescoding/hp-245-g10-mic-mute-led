## Test evidence (what the Tested-by: tag attests to)

Kernel `7.2.9-2-cachyos`, HP 245 14 inch G10 (board 8BA4), codec ALC236 on card 1.

- Machine booted 2026-10-17 12:16:59; the patched module loaded at 12:17:10
  (`snd_hda_codec_alc269`, srcversion `F1765E39CE2980EB493C18D`), so this is a
  boot-path result, not a reload.
- `modprobe.d` override removed and the interim `hda-coef35.service` disabled
  before the boot, so the kernel alone drives the lamp.
- The codec selected the new fixup instead of the vendor-wide fallback:

  ```
  snd_hda_codec_alc269 hdaudioC1D0: ALC236: picked fixup  for PCI SSID 103c:8ba4
  ```

- `hda::micmute` class device created; trigger `audio-micmute` bound
  (so the UCM/`snd_ctl_led` path reaches it).
- Microphone mute through `wpctl set-mute @DEFAULT_AUDIO_SOURCE@`:

  | state | `hda::micmute/brightness` | COEF `0x35` (raw) | bits 2-3 | lamp |
  |---|---|---|---|---|
  | muted | 1 | `0x8d66` | `01` | lit |
  | unmuted | 0 | `0x8d6a` | `10` | dark |

  COEF `0x35` is read-modify-write, so the raw value carries unrelated bits;
  only bits 2-3 are the lamp.
- `hda::mute` (F5, speaker) still follows the speaker mute — no regression.
- `verify-fix.sh` output: `RESULT: PASSED (kernel side verified end to end)`,
  0 FAIL, 0 SKIP.
- Patch: `checkpatch.pl --strict` → `0 errors, 0 warnings, 0 checks`.
